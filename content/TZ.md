# ТЗ: веб-база знаний по десктопному ПО «АСИК»

## 1. Контекст

Есть 10 презентаций (.pptx) — обучающие инструкции отдела АСУ по модулям десктопного приложения «АСИК» (система управления строительством). У всех презентаций одинаковая структура:

- Титул + название модуля
- Оглавление
- Цель обучения
- Общая концепция системы АСИК (единый блок, повторяется во всех 10)
- Блок «Десктопное приложение»: авторизация и выбор объекта → основные элементы интерфейса (добавление/удаление/редактирование/сохранение) → боковая панель → навигация → главное окно и смена объекта (тоже повторяется во всех 10)
- Уникальная часть: пошаговая инструкция по модулю («Шаг N — …», текст + 1-2 скриншота на шаг)
- Финальный слайд «Спасибо за внимание»

Список модулей (= разделы базы знаний):

1. Пользователи и права доступа
2. Паспорт объекта
3. Загрузка схем и локализация этапов строительства
4. Нормативная документация
5. График планёрок
6. Регистрация подрядчиков
7. СтроПро (назначение ТТК, объёмов, бригад)
8. Планирование графика работ
9. Контроль строительства
10. Оперативное управление (управление проектом)

**Вывод:** повторяющийся блок «Начало работы» нужно вынести в одну статью, а не дублировать в каждом модуле — это и есть главное отличие веб-версии от слайдов.

## 2. Цель

Перенести базу знаний из презентаций в веб-формат: единая структура статей, сквозной поиск, без дублирования общего контента, с возможностью дальше добавлять новые модули.

## 3. Аудитория

Сотрудники (инженеры, специалисты объектов, подрядчики), впервые осваивающие ПО АСИК или уточняющие работу конкретного модуля. Читают с ПК на объекте, часто по одному конкретному шагу — не всю базу подряд.

## 4. Информационная архитектура

```
Главная / Каталог разделов
├── Начало работы (общий раздел, 1 раз)
│   ├── Авторизация и выбор объекта
│   ├── Основные элементы интерфейса
│   ├── Боковая панель и навигация
│   └── Главное окно и смена объекта
└── Модули (10 разделов из списка выше)
    └── каждый: цель модуля + пошаговая инструкция (шаги со скриншотами)
```

- Раздел «Начало работы» — обязательная страница-пререквизит, на неё ссылаются все 10 модулей («сначала прочитайте базовые принципы работы»).
- Каждый модуль — это одна статья (лонгрид с шагами), а не набор мелких страниц, т.к. шаги линейны и осмысленны только по порядку. Внутри статьи — локальное оглавление (якоря по шагам), sticky при скролле.

## 5. Контент-модель статьи

Поля для каждой статьи (пригодится и для Figma, и для CMS/фронта):

| Поле | Описание |
|---|---|
| `title` | Название модуля |
| `slug` | URL |
| `category` | «Начало работы» / «Модули» |
| `order` | порядок в меню |
| `goal` | текст цели обучения (1 абзац) |
| `prerequisites` | ссылка на «Начало работы» |
| `steps[]` | массив шагов: `number`, `title`, `text`, `images[]` |
| `updatedAt` | дата последнего обновления инструкции |

Скриншоты из презентаций — вытащить как отдельные изображения (не картинкой всего слайда), обрезать по содержимому, привести к единому размеру/рамке.

## 6. Функциональные требования

**Обязательно (MVP):**
- Каталог разделов на главной, сетка карточек 10 модулей + отдельный блок «Начало работы»
- Страница статьи: заголовок, цель, пошаговый список (нумерация, текст, скриншот(ы) на шаг), локальное оглавление сбоку/сверху
- Клик по скриншоту → увеличение (лайтбокс)
- Поиск по названиям модулей и тексту шагов
- Хлебные крошки
- Кнопки «Предыдущая / следующая статья» (последовательное чтение модулей)
- Адаптив под десктоп в первую очередь (аудитория читает с ПК на объекте), мобильная версия — вторичный приоритет

**Желательно (v2):**
- Фильтр/тегирование статей по роли пользователя (например, «для прораба», «для администратора» — часть контента типа «Права доступа» доступна не всем)
- Блок «Была ли статья полезна» (да/нет) для сбора обратной связи
- Версионирование инструкций (дата обновления + история изменений, т.к. интерфейс АСИК меняется)
- Админ-панель для редактирования контента без разработчика (раз база будет расти)

## 7. Дизайн (Figma)

Экраны, которые нужно предусмотреть в макете:

1. Главная / каталог модулей
2. Страница статьи «Начало работы» (референс для повторяющихся общих блоков)
3. Страница статьи модуля (референс для лонгрида с шагами и скриншотами) — 1-2 варианта: с одним и с двумя скриншотами на шаг
4. Состояние поиска / результаты поиска
5. Мобильная адаптация ключевых экранов (каталог + статья)
6. Компоненты: карточка модуля, шаг инструкции (номер + текст + картинка), локальное оглавление, лайтбокс изображения, хлебные крошки, шапка/поиск

## 8. Технологии (предложение)

Под твой стек:

- **Фронт:** Next.js + TypeScript, контент — MDX или JSON-файлы по контент-модели из п.5 (для MVP не обязательно городить отдельную CMS — статей всего 10+1, можно хранить как структурированные файлы в репозитории)
- **Поиск:** на MVP — локальный (например, `flexsearch`/`fuse.js` по статичному индексу), без бэкенда
- **Хранение картинок:** просто `/public/images/<module>/step-N.jpg`
- **Если нужна админка для редактирования не-разработчиками (v2):** FastAPI + простая БД (Postgre/SQLite) под контент-модель из п.5, фронт остаётся тем же

Для MVP бэкенд можно не делать вообще — статичный Next.js сайт (SSG) полностью закрывает 10 статей + поиск.

## 9. План работ

1. Извлечь текст и скриншоты из презентаций → разложить по контент-модели (п.5) для всех 11 статей (10 модулей + «Начало работы»)
2. Дизайн в Figma по экранам из п.7
3. Вёрстка компонентов (Next.js) по дизайну
4. Наполнение контентом (MDX/JSON)
5. Поиск, лайтбокс, адаптив
6. Ревью контента (актуальность шагов) с отделом АСУ
7. Деплой

## 10. Критерии приёмки

- Все 10 модулей + «Начало работы» доступны как отдельные статьи, общий блок не задублирован
- Поиск находит статью по названию модуля и по тексту шага
- Скриншоты открываются крупно по клику
- Сайт открывается и читается на десктопе и мобильном
- Переход между статьями модулей без возврата в каталог (prev/next)

## Приложение: промпт для Cursor

```
Собери проект базы знаний на Next.js (App Router) + TypeScript + Tailwind.

Контент: 11 статей — "Начало работы" (общий раздел, 4 подтемы: авторизация и выбор
объекта, основные элементы интерфейса, боковая панель и навигация, главное окно и
смена объекта) и 10 статей-модулей (Пользователи и права доступа, Паспорт объекта,
Загрузка схем и локализация этапов строительства, Нормативная документация, График
планёрок, Регистрация подрядчиков, СтроПро, Планирование графика работ, Контроль
строительства, Оперативное управление).

Контент-модель статьи (храни как JSON в content/articles/<slug>.json):
{
  title, slug, category ("start" | "module"), order, goal,
  steps: [{ number, title, text, images: string[] }],
  updatedAt
}

Компоненты:
- ArticleCard — карточка модуля в каталоге на главной
- StepList — список шагов инструкции (номер, заголовок, текст, картинки)
- ImageLightbox — увеличение скриншота по клику
- ArticleToc — локальное оглавление статьи (якоря на шаги), sticky
- Breadcrumbs
- PrevNextNav — переход между статьями модулей по порядку
- SearchBar — поиск по title и тексту шагов, использовать fuse.js по статичному
  индексу, собранному на билде из content/articles/*.json

Страницы:
- / — каталог: отдельно карточка "Начало работы", отдельно сетка 10 карточек модулей
- /articles/[slug] — страница статьи с StepList, ArticleToc, Breadcrumbs, PrevNextNav
- поиск — модалка/дропдаун из шапки, не отдельная страница

Изображения клади в /public/images/<slug>/step-<n>-<i>.jpg, в JSON только пути.

Адаптив: десктоп — основной сценарий, мобильная версия — вторичная, но рабочая
(колонки в 1, оглавление сворачивается в аккордеон).

Дизайн минималистичный, без лишнего декора, крупный читаемый текст шагов, чёткая
нумерация шагов слева от текста.

Пока просто создай структуру проекта, компоненты-заглушки и JSON-схему для 2-3
статей с плейсхолдер-контентом — наполнение остальным контентом будет отдельным
шагом.
```
